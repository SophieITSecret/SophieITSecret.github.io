## 1. 概要とアーキテクチャ

TAKERUは、防衛・安全保障のトピックを1枚1テーマの「カード」で学ぶ学習アプリです。カードは **級 → 科目 → ジャンル → サブユニット** の階層で整理され、図表・本文・音声読み上げで構成されます。スマートフォンでの利用を主眼に、ホーム画面アプリ（PWA）として動きます。

### 技術スタック

- **フロントエンド** … 素のHTML / CSS / JavaScript（フレームワーク・ビルド工程なし）
- **PWA** … Service Worker によるオフライン対応、`manifest.json` でホーム画面追加に対応
- **データ** … CSVファイル2本（カード本体・リンク集）。DB・APIサーバーは持たない静的構成
- **ホスティング** … GitHub Pages（`git push` で即公開）
- **編集ツール（作業台）** … ローカルのNode.jsサーバー。公開物には含まれない

> **【設計方針】** サーバーを持たない静的サイトのため、**カードデータの追加・修正はCSVの編集がすべて**です。その編集を安全に行うのが「作業台」（第8章）です。

### ディレクトリ構成 `staging/TAKERU/`

```
staging/TAKERU/
├─ index.html        # 画面の骨格・SW登録・更新UI
├─ app.js            # 画面遷移・カード表示・音声・操作
├─ style.css         # スタイル（ダーク/ライト・レイアウト）
├─ sw.js             # Service Worker（キャッシュ・更新）
├─ manifest.json     # PWA定義
├─ TAKERUcard.csv    # カード本体データ
├─ MSlink.csv        # リンク集データ
├─ images/           # カード図表・バナー（.jpg）
├─ voices/           # 読み上げMP3 ＋ mp3list.json
└─ editor/           # 作業台（ローカル専用・非公開）
```

## 2. 画面構成と遷移

全画面と遷移は別紙**「画面遷移マップ」**に図示しています。ここでは内部状態（`navState`）と対応画面の一覧を示します。画面の出し分けは `app.js` の各 `show～()` 関数が担い、`navState` が現在位置を表します。

| navState | 画面 | 主な内容 / 遷移先 |
|---|---|---|
| `top` | トップメニュー | 受講／図書館／ニュース／リンク集／受験案内／使い方 |
| `subject` | 級・科目選択 | 1〜3級 × 3科目（現在3級のみ受講可）→ テーマ一覧 |
| `genre` | テーマ一覧 | 科目内のジャンル一覧 → カード一覧 |
| `sectionedlist` | カード一覧（章立てあり） | サブユニット見出しで区切られた一覧 → カード |
| `cardlist` | カード一覧（フラット） | 章立てのないテーマの通し一覧 → カード |
| `card` | カード本文 | 図表・本文・音声。送り／戻し／読み上げ／連続再生 |
| `complete` | ユニット完了 | 全カード読了時の完了表示 |
| `linkgenre` | リンク集：ジャンル | 外部リンクのジャンル別 → リンク一覧 |
| `linklist` | リンク一覧 | 個別リンク（外部タブで開く） |
| `placeholder` | 準備中 | 図書館・ニュース・受験案内・使い方の共通画面 |

> **【戻る操作】** **▲MENU と 下方向スワイプ**は「1つ上の階層へ」（`goUpOneLevel()`）。ただし**トップで下スワイプ**したときだけ起動画面へ戻ります。**TOP**はどこからでもトップメニューへ。

> **【未使用】** `showSectionMenu()` / `showCardList()` は旧実装で、現行フローからは呼ばれません。

## 3. データ構造 — カード（TAKERUcard.csv）

1行1カード。UTF-8（BOM付き）。本文は改行を含むため、必要に応じてダブルクオートで括られます。列は次の6つです（6列目はヘッダ名が空欄）。

| # | ヘッダ | 内容 | 例 |
|---|---|---|---|
| 1 | コード | カードID（一意・英字＋数字） | `ARM01` |
| 2 | ユニット | ジャンル（テーマ） | 自衛隊の武器・兵器 |
| 3 | サブユニット | 章立て（任意・空欄可） | 陸自装備 |
| 4 | タイトル | カード見出し | 10式戦車——日本最新鋭の主力戦車 |
| 5 | 説明 | 本文（複数行可） | 10式戦車。（ヒトマル式戦車）… |
| 6 | （無名） | 科目キー（級-科目名） | `3級-軍事と戦略` |

### 階層のなりたち

6列目の**科目キー**が最上位の区分（`3級-軍事と戦略` など）、**ユニット**がその中のジャンル、**サブユニット**がジャンル内の章です。サブユニットが空欄のジャンルは「フラットなカード一覧」になります。

- **科目キー** … `3級-軍事と戦略` / `3級-国家と法律` / `3級-戦争の歴史`（1級・2級は準備中）
- **ジャンル例（3級-軍事と戦略）** … 駐屯地基地ツアー／陸上・海上・航空自衛隊の基礎／組織と指揮系統／訓練と日常生活／戦士と実戦／日本周辺・世界の軍事情勢／自衛隊の武器・兵器

> ⚠️ **【注意・サブユニット名の重複】** **サブユニット名はジャンルをまたいで重複しうる**（例：「概論」が日本周辺と世界の両方にある）。一括リネーム等では必ず「ジャンル × サブユニット」で対象を絞ること。

### カードIDとバッジ

IDの末尾パターンで、タイトル横に種別バッジが自動表示されます。

| ID末尾パターン | 正規表現 | バッジ | 例 |
|---|---|---|---|
| 数字 + F + 数字 | `/\dF\d+$/` | **史実** | `IRUMA01F1` |
| 数字 + C + 数字 | `/\dC\d+$/` | **解説** | `IRUMA01C1` |
| 上記以外 | — | バッジなし | `ARM01` |

> **【補足】** 「F の前が数字」であることが条件です。`JPNDF01`（Fの前がD）のようなIDが誤って史実判定されないための規則です。ARM系は十の位で系統分け（01–04 陸／21–24 海／41–44 空／61–64 ミサイル）しています。

## 4. データ構造 — 画像・音声・リンク

### 画像 `images/`

- カード図表 … `images/{カードID}.jpg`（960×720基準・JPEG統一）。旧 `.png` はフォールバックとして参照
- バナー … `takeru-top.jpg`（トップ用フル）／ `takeru-menu.jpg`（サブメニュー用のコンパクト版）
- 画像の無いカードはプレースホルダ（⚔）を表示

> **【容量方針】** PNGは細密画で1枚1.5MB前後になり、端末キャッシュを圧迫していたため**JPEG（q90）に統一**。作業台の取り込みもJPEG保存。全体で約1/7に縮小済み。

### 音声 `voices/`

- 読み上げMP3 … `voices/{カードID}.mp3`
- `voices/mp3list.json` … MP3が存在するカードIDの一覧。**存在判定に使い**、無いカードは即システム音声（TTS）へ回す

### リンク集 `MSlink.csv`

| # | ヘッダ | 内容 |
|---|---|---|
| 1 | ID | 一意のリンクID |
| 2 | ジャンル | リンク集内の大分類 |
| 3 | 分野 | 小分類 |
| 4 | リンク先 | 表示名 |
| 5 | URL | 遷移先URL |
| 6 | 翻訳 | 下表のフラグ |

| 翻訳フラグ | 挙動 | 印 |
|---|---|---|
| 0 | そのまま外部タブで開く | — |
| 1 | Google翻訳（translate.goog）経由で開く | **JP** |
| 2 | そのまま開く（PDF資料の目印） | **PDF** |

## 5. 音声・読み上げ機能

音声は「録音済みMP3」を基本とし、無い場合や失敗時は端末の**システム音声（TTS）**に自動で切り替えます。下部コントローラーの**「音声」ボタン**で読み上げのON/OFFを切り替えます（`autoRead`）。

### 再生の判定フロー `playVoiceDirect()`

- **mp3list に無いID** … 即システム音声で本文を読み上げ
- **mp3list にあるID** … MP3をロード → `canplay` で再生。再生失敗／3秒タイムアウト時は、音声ONならTTSへ、OFFなら「音声データなし」警告を表示
- **iOS対策** … 起動時に無音WAVを一度再生し、オーディオをアンロック（ユーザー操作内で実行）

### 連続再生（自動送り） `autoAdvance`

- **▶ を長押し（700ms）**でモードON。ボタンが青く光る
- MP3の `onended` / TTSの `onend` で、700ms後に次カードへ自動送り
- ユニット末尾では次のサブユニットへ。無ければ完了画面へ
- 長押し判定は、指が14pxを超えて動いた（スクロール）ときのみ中止。ボタン文字の選択（青ハイライト）は `user-select:none` 等で抑止

> **【TTS】** `SpeechSynthesis`、言語 `ja-JP`、速度1.0。読み上げは本文（説明）テキストをそのまま読みます（作業台では別途「読み上げ原稿」を持たせることも可能）。

## 6. オフライン対応と更新（Service Worker）

`sw.js` がキャッシュを管理し、オフラインでも動作します。キャッシュ名は `takeru-vNN` 形式で、**デプロイのたびに番号を上げる**ことが更新のトリガになります。

### キャッシュ戦略 `fetch`

| 対象 | 戦略 | 理由 |
|---|---|---|
| `.csv` / `mp3list.json` | ネットワーク優先（失敗時キャッシュ） | データ更新を即反映 |
| 画像 / 音声（png・jpg・mp3） | キャッシュ優先（初回取得時に保存） | 再取得を避け高速化。404は保存しない（後から追加した画像が出る） |
| その他（HTML/JS/CSS） | キャッシュ優先 | アプリ本体の高速起動 |

初期キャッシュ（PRE_CACHE）: ルート・index.html・app.js・style.css・TAKERUcard.csv・MSlink.csv・アイコン各種・takeru-top.jpg。

### 更新フロー

- **自動** … 新しいSWを検出するとトースト「新しいバージョンがあります」→「更新する」で `skipWaiting` → リロード
- **手動（設定）** … 「🔄 最新に更新」で即チェック＆適用、無ければ現在バージョンを表示。「強制リセット」でSW登録とキャッシュを全消去して取り直す
- 現在バージョンは `GET_VERSION` メッセージでSWから取得して設定画面に表示

> ⚠️ **【iOS 起動時の画面高さ】** ホーム画面アプリで起動直後に `100dvh` が誤って小さく計算され、下部コントローラーに隙間が残る不具合があった。**body高さを `100lvh`（最大ビューポート＝常に全画面）に固定**して解消。`100dvh` は旧端末向けフォールバックとして残す。

## 7. UI・設定

### 下部コントローラー（5ボタン）

| ボタン | 働き |
|---|---|
| `TOP` | トップメニューへ一気に戻る |
| `▲ MENU` | 1つ上の階層へ（下スワイプと同じ） |
| `◀ / CARD` | カード画面では前のカードへ。メニュー画面では最後に見たカードへ復帰 |
| `▶` | 次のカードへ。長押しで連続再生 |
| `音声` | 読み上げのON/OFF |

### 設定（⚙）

- **カラーモード** … ダーク／ホワイト（`localStorage: takeru-theme`）
- **文字サイズ** … 小／中／大（`localStorage: takeru-font`）
- **アプリの更新** … 最新に更新／強制リセット／現在バージョン表示（第6章）

> **【保存されるもの】** 端末に保存するのは**テーマと文字サイズのみ**。カードの読了状況などの学習進捗は保存していません。

## 8. 作業台（編集ツール）

カードデータを安全に編集するためのローカル専用ツール。**公開物には含まれません**。Node.js標準の `http` だけで動く軽量サーバー（外部依存なし）で、`editor/public/` を配信します。

### 起動と設定 `editor/config.json`

```bash
# 起動
node editor/server.js   # → http://localhost:3000
```

```jsonc
// config.json
{
  "csvPath":       "…/TAKERUcard.csv",
  "imagesDir":     "…/images",
  "voicesDir":     "…/voices",
  "voicepeakPath": "",     // VOICEPEAK実行ファイル（音声生成に使用）
  "port":          3000
}
```

### 主な機能

- **カード編集** … タイトル・本文の編集（適用→CSV保存。保存時はバックアップを自動生成）
- **画像取り込み** … 元画像を960×720へ整え、SVGオーバーレイ合成、**JPEG化して保存**
- **音声生成** … VOICEPEAK連携でカード本文からMP3を生成（一括録音対応）
- **一括取り込み** … `@カードID` 形式のテキスト（AI出力など）から本文をまとめて反映
- **書き出し** … レビュー用にMD／自己完結HTMLを出力。書き出すカードをチェックで選択（未作成を外す等）
- **リネーム** … ユニット名・サブユニット名を該当カード一括で変更（ジャンル×サブユニットで対象を厳密に絞る）
- **進捗ボード** … 本文・画像・音声の作成状況を一覧
- **プロンプトメモ／読み上げ原稿** … テンプレート管理と、本文と別の読み仮名テキスト

### APIエンドポイント `editor/server.js`

| メソッド・パス | 用途 |
|---|---|
| `GET/POST /api/csv` | CSVの読み込み・上書き保存（バックアップ付き） |
| `GET /api/images` · `POST /api/images/save` | 画像一覧・JPEG保存 |
| `GET/POST /api/voice/*` | ナレーター一覧・MP3一覧・状態・音声取得・生成（VOICEPEAK） |
| `GET/POST /api/prompts` | プロンプトテンプレート |
| `GET/POST /api/voice-settings` | 音声パラメータ設定 |
| `GET/POST /api/reading-scripts` | 読み上げ原稿 |

> ⚠️ **【CSV編集の鉄則】** 本文は**多行の引用フィールド**を含むため、PowerShell等の行単位処理は構造を壊す実績あり。列の編集は**作業台（またはエディタの厳密な差し替え）を必ず経由**すること。

## 9. デプロイと運用

### 公開手順

```bash
# 1. sw.js のバージョンを1つ上げる（キャッシュ更新のトリガ）
#    const SW_VERSION = 'v30';
#    const CACHE_NAME = 'takeru-v30';

# 2. コミットして push（GitHub Pages が自動公開）
git add -A && git commit -m "…"
git push origin main
```

> ⚠️ **【最重要】** ファイルを変えても **sw.jsのバージョンを上げ忘れると、利用者の端末は古いキャッシュのまま**になります。デプロイのたびに `SW_VERSION` と `CACHE_NAME` を必ず1つ上げること。

> **【別プロジェクトとの区別】** TAKERUの公開は **GitHub Pages（git push）**。姉妹プロジェクト「BarSophie」は `firebase deploy` で、手順が異なります（混同注意）。

### 反映確認の目安

- スマホ側は「🔄 最新に更新」または更新トーストで反映。iOS起動時の挙動に関わる変更は**アプリを開き直して**確認
- 作業台を開いている場合は、CSVを触った後**ブラウザを再読み込み**してから保存（古いデータでの上書き防止）
