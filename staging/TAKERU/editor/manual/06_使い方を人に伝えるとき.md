# 使い方を人に伝えるとき

ソフィーや制作の AI、ほかの担当、あるいは人に、作業台まわりの仕事を頼むときの伝え方です。

## いちばん大事なこと：AI は作業台を操作できない

- 作業台は、このパソコンの中でしか開けません。ソフィーや制作の AI は、作業台のボタンを押せません。
- AI に教えるのは **「作業台に渡す形」** です。たとえば、搬入の置き場に入れるフォルダの形や、制作デスクの依頼書への返し方です。ボタンの押し方ではありません。
- 形が違うと、作業台は受け取れません（搬入なら差し戻し、デスクなら読み取れない）。だから、**形の決まりのファイルを渡して、そのとおりに作ってもらう**のが基本です。

## 相手がどこを読めるか

| 相手 | 読める所 | 渡し方 |
|---|---|---|
| ソフィー・マガジン（Cowork）・事務局・企画参謀・制作の AI（claude.ai・ChatGPT・Gemini） | Google ドライブの `TAKERU_共有`、ネットの住所 | ドライブのファイルの場所か、下の GitHub の住所 |
| Claude Code の担当（ホームくん・会員システム など） | このパソコンのフォルダ | ファイルの場所（`D:\Sophie\SophieITSecret.github.io\staging\TAKERU\editor\manual\`） |
| 人（作業台を代わりに使う人） | 作業台の画面 | 「📖 使い方」の章の名前 |

**このマニュアルを、ネットの住所で渡すとき**（GitHub。公開されています）：

- 章の一覧：`https://github.com/SophieITSecret/SophieITSecret.github.io/tree/main/staging/TAKERU/editor/manual`
- AI にそのまま読ませるとき（飾りの無い文）：`https://raw.githubusercontent.com/SophieITSecret/SophieITSecret.github.io/main/staging/TAKERU/editor/manual/` の後ろに、章のファイル名（例 `03_搬入.md`）
- ネットを見られない AI には、md ファイルをそのまま添えて渡します。

## 相手ごとに渡すもの

| 相手 | 頼むこと | 渡すもの |
|---|---|---|
| ソフィー | 自由研究の原稿の搬入 | `TAKERU_共有\60_自由研究の搬入\搬入の決まり.md` |
| 制作の AI（CP制作1・G制作1・CL制作1・企画参謀） | テーマの調査・カード割り・骨組み・本文 | 制作デスクが作る**依頼書**（デスクで写す）。返事の形は、依頼書の「■ 返事の形」に入っている。くわしくは「制作デスク」の章の3節 |
| マガジン・ホームくん など別担当 | 作業台に関わる頼み事・知らせ | 提出箱の報告。作業台の中身を説明するときは、この章の GitHub の住所 |
| 人に作業台を任せる | 作業台の操作 | 「はじめに」と「カードの基本作業」の章。最初の1回は横で一緒にやる |

## 写して使える文

```写す:ソフィーへ（搬入の頼み）
自由研究の原稿の搬入をお願いします。
決まりは TAKERU_共有\60_自由研究の搬入\搬入の決まり.md です。読んでから、
受付\<講座名>\ の中に、テーマごとのフォルダ（台帳.csv・01.txt…・01.jpg…）を入れてください。
講座がまだ講座一覧.md に無いときは、入れずに知らせてください。入れたら教えてください。
```

```写す:制作の AI へ（依頼書の前に一言）
このあと貼る依頼書は、TAKERU の作業台（制作デスク）で作ったものです。
返事は、依頼書の「■ 返事の形」のとおりにしてください。形が違うと、作業台で受け取れません。
分からないところは、推測で埋めずに「不明」と書いてください。
```

```写す:AI に作業台の仕組みを説明したいとき
TAKERU の作業台（カードを作って公開するための道具）の使い方は、次の住所の md にあります。
https://github.com/SophieITSecret/SophieITSecret.github.io/tree/main/staging/TAKERU/editor/manual
あなたは作業台を操作できません。作業台に渡すもの（ファイルの形や、返事の形）を守ってもらうために読んでください。
```

```写す:Claude Code の担当へ
TAKERU の作業台の使い方は D:\Sophie\SophieITSecret.github.io\staging\TAKERU\editor\manual\ の md にあります。
「○○」の章を読んでから進めてください。作業台のプログラムを直すときは、TAKERU担当（このフォルダの CLAUDE.md）に伝えてください。
```

## 教えるときのこつ

- **一度に全部教えない。** 相手の仕事に関わる章やファイルだけを渡します。
- **最初の1回は小さく試す。** 搬入なら1テーマ1枚、制作なら1枚。形の食い違いを先に見つけます。
- **説明を写さない。** 決まりを変えたら、元のファイル（搬入の決まり.md や、この md）を直します。相手には「直したので読み直して」とだけ伝えます。報告や会話に説明を書き写すと、2か所になって食い違います。
- **GitHub の住所で読めるのは、コミットした後の中身です。** md を直したら、Claude Code に「マニュアルの直しをコミットして」と頼みます。土曜の自動転送は、マニュアルを送りません。
- **公開されていることを忘れない。** このマニュアルは誰でも読めます。パスワード・鍵・会員の名前やメールアドレスは書かないでください。
